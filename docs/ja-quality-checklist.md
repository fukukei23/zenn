# 日本語品質 手動レビューチェックリスト（10項目）

> Phase 0項目④成果物（2026-09-24・設計正典: obsidian-ssot 01_DECISIONS/claude-code/2026-09-23_日本語文章品質保証3層統合案）
> 使い方: 公開前の層3（AI点検）+層1（suiko）実施後に、本チェックリストで人間が最終確認する。
> 層3の指摘は**自動適用しない**=全て人間レビュー経由（AIの修正案自体が壊れる実例あり・項目7）。

- [ ] **1. 意味破綻（最上位）**: 文全体として意味が成立しているか。主語と述語の対応が崩れ「何についての何か」が読み取れない文がないか（2026-09-24実例: 「自分は大丈夫と思って読んでいただけると思っています」=二重使用以前に意味不成立）
- [ ] **2. 主語のすり替え**: 文の途中で主語（誰が・何が）が勝手に変わっていないか
- [ ] **3. 同じ言葉の二重使用**: 「思って…と思っています」型の重複で意味不明になっていないか
- [ ] **4. 誤字・脱字・変な助詞**: 「必要がる」型の誤字・変な助詞がないか
- [ ] **5. 翻訳調の破綻**: ネイティブが言わない直訳調の長文がないか
- [ ] **6. 敬語の不自然な接続**: 「〜いただける想いです」型の、文法的に通るが不自然な言い回し（層3は検出可能な実測あり・層1は検出しない）
- [ ] **7. AIの修正案自体の自然さ確認**: 層3が提示した修正案をそのまま採用しない。修正案の日本語自体が破綻することがある（2026-09-24実例: AIの修正案「お読みいただける想いです」がふくけい指摘で不自然と判明）
- [ ] **8. suiko警告の扱い**: 層1の警告は参考提示（info相当）・redundant_light_verb/hype_expression以外の警告は多くが正当な書式へのhint。警告に過剰反応して文書構造を壊さない
- [ ] **9. 数字・固有名詞の正確性**: 実績数値は数値マスターと突合・API名/バージョンは一次ソース確認（日本語品質外だが公開前の必須確認）
- [ ] **10. 長文の分割点検**: 本文が12,000字を超える場合、層3は分割して点検済みか（16,000字超は点検不能になる実測あり・ja_qualityが警告表示）
