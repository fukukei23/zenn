## はじめに

CLIツールを書くとき、エラーの種類を終了コード（exit code）で呼び出し側に伝えたい場面はよくあります。しかし「0が成功、1が失敗、あとは適当でいい」という感覚で番号を選ぶと、同じパイプライン内の他ツールと衝突し、原因の切り分けを難しくすることがあります。

私はMarkdownで書いた記事をHTMLへ変換するCLIツールを運用しています。以前「変換後のHTMLのcommit漏れで公開ページが404になる」という事故が起きたため、**生成物がGit管理下（tracked）にあるかをチェックし、漏れていれば警告して異常終了する**機能を追加しました。最初は終了コード5を使ったのですが、これがpytestの予約済みコードと完全に一致していました。この記事では、衝突の発見から78への変更までを具体的なコードと一緒にまとめます。
