## はじめに

Claude Code を日常的に使っていると、こんな場面に出会いませんか。

対話の途中で AI が「見積りを提示してから進めます」と宣言したのに、数ターン後の最終報告にはその話が一切出てこない。拒否されたわけでも、訂正されたわけでもない。**約束だけが静かに消えている**。

私はこの現象を「無言のすり減り」と呼び、自分の Claude Code 設定リポジトリにある outward-reply スキルの「失敗⑪」「失敗⑫」として対策を進めてきました。本記事では、精読シートを 7 権化して**約束突合欄**を追加し、**原文引用の二択を強制**する具体設計を紹介します。

## 「無言のすり減り」の正体

### 失敗⑪：過去約束の無言のすり減り

最初に潰すべきだったのは、AI 側が対話中に**自発的に宣言したこと**が、後続の応答で言及なく薄まる問題です。

実例として、ある案件で「見積りを後で提案します」と AI が述べたのに、最終報告には見積りの話が一切なく、私が指摘して初めて「言ったのにやっていなかった」ことが発覚したケースがありました。悪意はなく、LLM が直近の文脈に引きずられて古い発言の重みを落としてしまう、注意力の問題です。

つまり、意志で守らせるのではなく、**照合する仕組み**が必要です。

### 失敗⑫：将来可能性の残響による空約束

もう一つ厄介なのがこちら。「解決できませんが、将来は〇〇になる可能性があります」といった言い回しです。丁寧な印象がありますが、この「可能性の言及」が後続の対話で**約束に化け**、追跡対象として残響し続けます。突破不能と確定した案件こそ、空の約束を残さない書き方が求められます。

## 精読シート 7 権化の具体設計

### 権構成

outward-reply スキルでは、応答前に対話を精読させる「精読シート」を強制しています。従来は 6 権でしたが、約束突合権を追加して 7 権にしました。

| # | 権 | 役割 |
|---|---|---|
| 1 | 要件要約 | 相手（ユーザー）の要求整理 |
| 2 | 暗黙の前提 | 文面にない前提の洗い出し |
| 3 | 実行可否判定 | 対応可・不可・条件付きの判定 |
| 4 | **過去約束（自側抽出）** | 対話全文から AI 自身の約束を抽出 |
| 5 | **約束突合** | 各約束ごとに「守った／見送り＋理由」を記載 |
| 6 | **原文引用** | 約束の原文をそのまま貼る |
| 7 | 対応方針 | 最終的な行動計画 |

ポイントは 3 つです。

1. **Phase 0 での自側約束抽出**：相手の要求を読むだけでなく、AI 自身が過去に発した約束を対話全文から抜き出す工程を明示的に設けました
2. **原文引用の二択強制**：権 6 は「原文をそのまま引用する」か「該当なしと明記する」の二択のみ。要約・言い換えを禁止することで、曖昧化によるすり減りを構造的に防ぎます
3. **簡易モードでも省略不可＋秘匿時フォールバック**：短い応答モードでも約束突合だけは省略させません。原文を貼れない事情がある場合は「引用不可＋理由」を書かせます

この設計は 2 機の LLM による相互レビューで 15 指摘を受けて打磨しました。特に「簡易モードの抜け道」と「秘匿時に書けなくて止まる」の 2 点は、実際に運用しないと見えない穴でした。

### 突合チェッカーの簡易実装

仕組みの骨格を Python で示します。対話ログから自側の約束文を抽出し、最終応答と**原文ベース**で突合するだけのシンプルなものです。

```python:promise_checker.py
import re
from dataclasses import dataclass

# 「約束」とみなす発言のパターン（例示）
PROMISE_PATTERNS = [
    r"今後は[^。]+します",
    r"次回から[^。]+します",
    r"[^。]+ことを?約束します",
    r"後ほど[^。]+提示します",
]

@dataclass
class PromiseCheck:
    promised: str          # 約束の原文
    quoted_or_declared: bool  # 原文引用 or 見送り宣言があるか

def extract_promises(dialog: list[dict]) -> list[str]:
    """対話全文から自側（assistant）の約束文を抽出する"""
    promises: list[str] = []
    for turn in dialog:
        if turn["role"] != "assistant":
            continue
        for pat in PROMISE_PATTERNS:
            promises += [m.group(0) for m in re.finditer(pat, turn["text"])]
    return promises

def cross_check(promises: list[str], final_reply: str) -> list[PromiseCheck]:
    """約束と最終応答を原文ベースで突合する"""
    results = []
    for p in promises:
        # 原文引用がある、または「見送り＋理由」が明記されているか
        ok = (p in final_reply) or ("見送り" in final_reply)
        results.append(PromiseCheck(promised=p, quoted_or_declared=ok))
    return results

# 使い方のイメージ
dialog = [
    {"role": "user", "text": "この案件、進めていい？"},
    {"role": "assistant", "text": "見積りを後ほど提示します。まず調査します。"},
]
for r in cross_check(extract_promises(dialog), final_reply="調査が完了しました。"):
    print(f"{'OK ' if r.quoted_or_declared else 'NG '} {r.promised}")
    # => NG 見積りを後ほど提示します。
```

`NG` が出たら、応答前に「見積りを後ほど提示します」という約束が未処理だと機械的に分かります。正規表現は簡素化していますが、実運用では失敗⑫対策として「可能性があります」という言い回しを約束から除外するフィルタも入れています。

## 中途半端報告禁止と成功条件の明示

精読シートで見える化しても、**報告自体が曖昧**なら元も子もありません。あるツール提案の場面で「提案しました」という報告しかなく、提案が相手に受け入れられる条件が一切検証されていない事故を教訓に、「最小5禁止」ルールに**中途半端報告禁止**を追加しました。

- 機能提案時は**成功条件を明示**してから報告する
- 「一部だけ成功・未検証項目に触れない」報告を禁止する
- 可能性の言及には期限か条件をセットし、無条件の楽観を書かない

書き方の例です。

- ❌ 「対応しました」
- ✅ 「対応しました。確認できた点：X。未確認な点：Y（理由：Z、確認方法：W）」

## おわりに

本記事の要点をまとめます。

1. AI の約束忘れは意志の問題ではなく注意力の問題なので、**構造（突合工程）で守らせる**
2. 精読シート 7 権化（約束突合欄追加・原文引用二択強制・省略不可・秘匿フォールバック）で曖昧化を構造的に塞ぐ
3. 報告側も「中途半端報告禁止＋成功条件の明示」で締めて、初めて一貫する

LLM の相互レビューで指摘をもらう運用も、自分一人では気付けない抜け道を見つける意味で非常に有効でした。皆さんの Claude Code 運用でも、「AI が言ったこと」と「AI がやったこと」を照合する仕組みを一度設計してみてください。
