## はじめに

「MiniMaxに切り替えました」——そうLLMが宣言したのに、statusコマンドは未実行で、statuslineの表示は前の状態のまま。こうした**発話と実状態の乖離**は、エージェント運用では見過ごしがちな不具合の温床です。

自分のClaude Code設定リポジトリでは、この問題へ対処する**status-first規則**（切替系発話 → 機械的トリガー検出 → status実測必須）を導入し、複数LLMによる多段レビュー（r1〜r4）を経て設計を洗練させてきました。本記事では、その中でも「うまく動かなかったときにどう落ちるか」を決める**フォールバック設計**に絞って、具体コード付きで解説します。

## status-first規則の全体像

規則の骨子はシンプルです。

1. **切替系発話を検出したら**（「〜に切り替えました」「proxy-modeに移行」など）
2. **statusコマンドの実測を必須にする**
3. 実測結果を所定の形式で報告し、応答を**終端**する

検出は正規表現による機械的トリガーで行います。LLMに「正直に報告してね」と頼るのではなく、**発話という観測可能な文字列をトリガーにする**のがポイントです。判定を機械に寄せることで「言った／言っていない」の揺れを排除できます。なお同一応答内での実行義務（過去の実測結果の流用禁止）や、切替前後の二点測定も条文に含めていますが、本題から外れるため詳細は割愛します。

## フォールバック設計の3つの決定事項

レビューで特に議論になったのが、検出や注入が失敗した場合の挙動です。最終版（r4）では次の3点を明文化しました。

### ① 出力ドラフト判定の廃止 — 入力発話判定のみに一本化

当初はLLMが出力中のドラフト文章も判定対象にしていましたが、これは廃止しました。書きかけの確定前テキストをトリガーにすると誤検出が増えるうえ、ストリーミング処理に依存してテストの決定論性（同じ入力に同じ結果を返す性質）が保てなくなるためです。入力側の確定した発話だけに絞ることで、判定関数が純関数になり回帰テストが書きやすくなります。

### ② peak_block拒否時は固定テンプレート＋再試行1回限り

規則を応答へ注入する仕組みが、負荷などの理由でブロック・拒否される（自分の実装ではpeak_blockと呼んでいます）ことがあります。ここで「拒否されたら再送」を素朴に実装すると、拒否が続く限り無限再試行に陥ります。そこで**拒否時は固定テンプレートに差し替え、再試行は1回限り**と定義しました。最悪でも固定文言が出ることを保証しつつ、ループを機械的に断ち切ります。

### ③ status失敗の機械的定義と3点報告終端

「statusが失敗した」を感覚に任せると曖昧です。そこで**statusコマンドの出力が得られないこと**と機械的に定義し、失敗時はprovider・model・使用率の**3点を報告して応答を終端**すると規定しました。終端を強制することで、「失敗したまま次の作業に進む」ことを防ぎます。

## 実装例（Python）

以上を素朴なPythonに落とすと次のようになります（実際のリポジトリから簡略化しています）。

```python
import re

# 切替系発話の機械的トリガー（過剰検出を許容して広めに取る）
TRIGGER_PATTERNS = [
    r"切り替え",           # 「〜に切り替えました」
    r"に変更しました",
    r"proxy[- ]?mode",     # 「proxy-modeに移行」
    r"状態を確認",         # 状態確認形トリガー
]

# peak_block（注入拒否）が続いたときの代替文言
FALLBACK_TEMPLATE = (
    "[status-first] statusの実測報告が未検出です。"
    "provider / model / 使用率 の3点を報告して応答を終端してください。"
)

def detect_switch_utterance(text: str) -> bool:
    """切替系発話の判定。入力発話のみ対象（出力ドラフトは判定しない）"""
    return any(re.search(p, text) for p in TRIGGER_PATTERNS)

def inject_rule(rule: str, peak_block: bool) -> str:
    """規則の注入。拒否されても再試行は1回限りで打ち切る"""
    for _ in range(2):  # 初回 + 再試行1回
        if not peak_block:
            return rule
    return FALLBACK_TEMPLATE  # 固定テンプレートで確定し無限再試行を禁止

def build_reply(utterance: str, status_output: str | None) -> str:
    if not detect_switch_utterance(utterance):
        return ""  # トリガーなし → 通常応答へ
    if status_output is None:  # status失敗の機械的定義
        return FALLBACK_TEMPLATE
    return f"status実測: {status_output}"  # 3点報告して終
